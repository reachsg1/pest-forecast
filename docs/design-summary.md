# 병해충 발생 예측 서비스 설계서 (요약본)

작성일: 2026-11-09 · 전체 설계서(구성도·사이트맵·와이어프레임 포함): https://claude.ai/artifact/Ldjcj8vhZbst188usZQZLF

## 1. 개요
- 목적: 청이 보유한 기상·예찰 데이터로 병해충 종류별 발생 위험도를 매일 산출하고 지도·농장 단위로 공개하는 공공 웹 서비스. 코드·모델은 GitHub, 웹은 Vercel 배포.
- 1차 대상: 벼·사과·고추의 주요 병해충 8종, 3·7·10일 전망.
- NCPMS 대비 추가 가치: 모델 카드(입력변수·임계값·근거) 공개, 농장 좌표 입력, 연도별 검증 지표 공개, JSON Open API·CSV 재개방.
- 제외(링크 연계): 영상 진단, 전문가 상담, 문자·알림톡 발송.

## 3. 예측 모델 체계
| 유형 | 대상 | 입력 | 산출 | 1차 예시 |
|---|---|---|---|---|
| A 감염 조건 모델(규칙) | 기상 의존 곰팡이·세균병 | 잎젖음시간, 강우일수·강우량, 평균기온, 일조 | 온도×젖음시간 임계표 → 감염지수, 연속 감염일 누적 | 사과 탄저병, 벼 잎도열병, 고추 탄저병·역병 |
| B 발육 단계 모델(적산온도) | 세대가 뚜렷한 해충 | 일최고·최저기온, 발육영점, 세대별 요구량 | 생물기준일부터 적산 → 성충 발생·산란·부화 피크 | 복숭아순나방, 담배나방, 벼물바구미 |
| C 통계·ML | 비래·돌발·복합 기작 | 최근 30일 기상 통계, 전년 동기 예찰, 지역·시기 | 예찰조사 정답으로 GBM/로지스틱 → 발생 확률 | 벼멸구·흰등멸구, 잎집무늬마름병 |

- 위험도 등급(4단계, NCPMS 용어 정렬): 정상 0~24 / 예보 25~49 / 주의보 50~74 / 경보 75~100.
- 생물계절 판정(2026-11-10 추가): 작물이 재배되지 않는 시군(`cultivation.csv`, 농업경영체 등록정보 재배면적)이거나 재배 기간 밖(`crop_calendar.yaml`, 시군 > 시도 > 권역 > 전국)이면 위험지수를 내지 않고 **해당 없음**(사유: 비재배지 / 재배 시기 아님)으로 발행. 해당 없음은 등급이 아니며 등급 집계에서 제외. 화면은 무채색·점선 테두리로 등급색과 구분. 자료가 없는 작물은 판정 생략 + 경고.
- 모델 레지스트리: `models/<작물>/<병해충>/` 폴더에 `model.yaml`(모델 카드), `model.py`(`predict(weather_daily, forecast_daily, history) -> RiskSeries`), `eval.json`(연도별 검증). 폴더 추가만으로 화면 자동 반영.
- 1차 대상: 벼(잎도열병 A, 잎집무늬마름병 C, 벼멸구·흰등멸구 C), 사과(탄저병 A, 복숭아순나방 B), 고추(탄저병 A, 역병 A+토양수분, 담배나방 B — 11-10 담배거세미나방에서 교체).

## 4. 시스템 아키텍처
데이터 소스(농업기상·NCPMS·기상청·예찰 CSV) → GitHub Actions 일일 배치(수집→정제→모델 실행→결과 산출) → 저장(Vercel Blob + Postgres/Neon, 저장소 `data/` 스냅샷) → Vercel Next.js 앱(서버 라우트 `/api/*`, 페이지, 크론) → 사용자(농업인·지도사 웹/모바일, 지자체·민간 Open API).
- 예측 계산은 Vercel 서버리스가 아닌 GitHub Actions에서 수행(실행시간·무상태 제약 회피, Python 모델 그대로 사용).
- 배치 순서: 전일 관측 수집 → 예보 결합 → 결측 보간·파생변수(잎젖음시간, 적산온도) → 모델 순회 실행 → Parquet/JSON 저장 → 크론 호출로 캐시 갱신 → 실패 시 전일 결과 유지 + Issue 자동 생성.
- 연구자 흐름: 모델 폴더 PR → Actions 백테스트(과거 3개년) → Vercel 미리보기 URL → 담당자 승인 → main 병합·배포.

## 7. 데이터 모델·API
- 테이블: `spot`, `weather_daily`, `pest`, `model`, `prediction`(최근 30일 DB, 이전은 Parquet), `survey`, `farm`(3단계).
- API: `GET /api/v1/risk`(지도), `/risk/spot/{code}`(추이), `/risk/nearest`(농장), `/pests`, `/pests/{id}/control`(NCPMS 변환), `/survey`, `/models/{id}/eval`, `/status`, `POST /api/cron/refresh`.
- 외부 API 키는 서버·Actions에서만 사용. 공공데이터포털 키는 디코딩된 형태로 환경변수에 저장.

## 10. 리스크·고려사항
- API 키가 프로젝트 지침에 평문 → Secrets/환경변수로 이관 후 삭제.
- 농업기상 개발계정 1,000건 한도 → 월별·기간 조회로 절감, 활용사례 등록 후 운영계정.
- NCPMS 예찰·예측 서비스 코드 미확인 → OpenAPI 안내 확인 또는 재해대응과 협조.
- 예찰 지점↔기상 지점 불일치 → 최근접 매칭 + 거리·고도차 임계, 2단계 30m 격자 대체.
- 문헌 임계값의 국내 적합성 → 검증 화면 공개, 백테스트 보정, '예측' 명시.
- 공공기관 외부 클라우드 호스팅 → 개인정보 미저장 공개 서비스로 한정, 정보보안 부서 사전 협의, 정적 사이트 내보내기 경로 확보.
- NCPMS와의 등급 차이 → 나란히 표시·차이 설명, 장기적으로 모델 플러그인을 NCPMS에 탑재.
