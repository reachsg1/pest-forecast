# 기상청 ASOS 일자료 추가 효과 검증 (2026.11.13.)

농업기상 관측(현재 학습·예측에 쓰는 자료)에 기상청 ASOS(종관) 일자료를 더하면 예찰 기반 발생 예측이 나아지는지 확인했다.

## 자료
- ASOS: 공공데이터포털 기상청_지상(종관, ASOS) 일자료 조회서비스, 98개 지점, 2015.1.1.~2026.11.12. (`scripts/fetch_asos.py`, 캐시 `data/cache/asos/daily`, 공공누리 1유형)
- 지점 → 시군: 지점정보 API가 API허브 전용이라, 지점명이 가리키는 시군으로 정했다(대도시는 관측소 소재 구). `data/reference/asos_stations.csv`
- 표본마다 예찰 시군에서 가장 가까운(자료 있는) ASOS 시군의 조사일 전날까지 값. 예찰 표본 절반 이상이 같은 시군에 ASOS가 있었다(거리 중앙값 0 km). 농업기상도 표본의 90% 이상이 같은 시군 관측소다.
- 새 항목: 일조·일사·강수 지속시간(14일·시즌), 풍속, 이슬점, 구름양, 최저습도, 습한 날(평균습도 85% 이상) 수

## 방법
`python -m pipeline.asos_eval --pest <pest>`: 연도 분리(고추·사과 복숭아순나방 학습 2015~2022 / 시험 2023~2026, 사과 탄저병 2021~2023 / 2024~2026), Random Forest(잎 최소 20, 배포 모델과 같음), 난수 3개 평균.
- A 기존(농업기상) / B +ASOS 새 항목 / C +ASOS 전체(새 항목 + ASOS로 다시 계산한 기온·습도·강수) / D 가까운 쪽 관측 + 새 항목
- 지표: 전체 AUC, 같은 회차 AUC(같은 날 시군 사이 순위 = 지도에서 어디가 더 위험한지 가리는 힘)
- 결과 파일: `data/survey/eval_<pest>_asos.json`

## 결과 (기상+직전예찰 = 배포 모델과 같은 피처)

| 병해충 | AUC A → B | 같은 회차 AUC A → B (C) |
|---|---|---|
| 고추 탄저병 | 0.886 → 0.887 | 0.741 → 0.749 (0.761) |
| 고추 역병 | 0.879 → 0.888 | 0.781 → 0.813 (0.810) |
| 고추 담배나방 | 0.882 → 0.885 | 0.776 → 0.800 (0.800) |
| 사과 복숭아순나방 | 0.870 → 0.869 | 0.849 → 0.854 (0.871) |
| 사과 탄저병 | 0.893 → 0.890 | 0.782 → 0.779 (0.780) |

기상만(직전 예찰 없이): 다섯 종 모두 AUC +0.004~+0.021, 같은 회차 AUC 고추 +0.03~+0.08.

## 해석
- 고추 3종: 전체 AUC는 거의 같지만 **같은 날 시군 간 순위(같은 회차 AUC)가 꾸준히 +0.01~+0.03** 좋아졌다. 지도의 '어디가 더 위험한가'에 해당하는 능력이라 의미가 있다. 날씨만 쓰면 효과가 더 크다(직전 예찰값이 많은 부분을 설명하기 때문).
- 사과: 표본이 적고(600건 안팎) 차이가 잡음 수준(±0.01)이라 판단 보류.
- 가까운 쪽 관측으로 바꾸기(D)는 B와 차이가 없다 — 농업기상이 이미 대부분 같은 시군 관측이라 거리 이득이 작다. 효과는 **새 항목(일조·일사·강수 지속시간·바람 등)** 에서 온다.

## 배포 결과 (2026.11.13.)
배포 절차 그대로(`python -m pipeline.survey_ml --pest <pest> --asos [--static terrain] --export`, 학습 2015~2022·시험 2023~2025, 하이퍼파라미터는 학습 연도 교차검증, 난수 1개)로 다시 학습해 기존 배포 모델과 비교했다.
그 전에 **강수 지속시간 오류를 고쳤다**: 98곳 중 약 71곳은 이 항목을 재지 않아 늘 빈칸인데, 위 검증에서는 빈칸을 0으로 셌다. 지금은 그 해에 값이 한 번이라도 있는 지점만 빈칸=0(비 없음), 아니면 자료 없음(학습 평균으로 채움)으로 본다.

- 위 표(검증)보다 효과가 작다: 강수 지속시간 0 처리가 지점 구분 효과를 만들었던 것으로 보이고, 배포 모델은 지형 피처·하이퍼파라미터 조정이 이미 들어가 있다. 차이는 대부분 난수 수준(±0.005)이라 **큰 개선이 아니라 '손해 없이 조금'** 수준이다.
- 반영 모델: 역병·담배나방의 RF·XGBoost(앙상블에 포함). 로지스틱(survey_hist)은 그대로.
- 배치: `pipeline/asos.py` — 매일 지점당 1건(약 98건) 올해 일자료를 전날까지 받아 `data/cache/asos`(Actions 캐시)에 두고, 지점 시군(없으면 가장 가까운 ASOS 시군) 값으로 a_* 피처를 만든다. 예보 날짜는 발행일 값. 실패하면 학습 평균으로 채우고 경고(status.json `asos`·warnings).
- ASOS 일자료가 새벽 5시에 전날 것까지 나오는지는 운영에서 확인 필요(늦으면 이틀 전까지로 계산, 최근 30일 중 25일 기준은 충족).
